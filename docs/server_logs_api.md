# Server Logs API

Redmine のログフォルダー（`log`）の直下にあるファイルの一覧と、ファイルの指定した範囲のバイトを返す API。

ログを読んで返すだけの汎用の API で、絞り込み・集計は呼ぶ側で行う。数 GB のログでも、範囲を区切って順に読めば、応答が大きくなりすぎずに読み切れる。

## エンドポイント

| エンドポイント | 説明 |
|---------------|------|
| `GET /server_logs.json` | ログのファイルの一覧と、今 Redmine が書いているファイルの名前 |
| `GET /server_logs/content.json` | ファイルの範囲のバイト。成功のときは JSON ではなく、バイトをそのまま返す（失敗のときだけ JSON） |

JSON だけに対応する（XML は無い）。

## 権限

システム管理者だけが使える。

| ステータス | いつ |
|-----------|------|
| 401 | API キーが無い・無効（本体の `login_required` 設定に関わらず） |
| 403 | システム管理者でない |

失敗のときの本文は、どれも `{"errors":["…"]}` の形。

```json
{ "errors": ["administrator required"] }
```

## 読めるファイル

読めるのは、ログフォルダーの直下にあって、一覧に並ぶファイルだけ。ログフォルダーの外のファイルは読めない。

ログフォルダーは、Rails のログの設定（`config.paths['log']`）のフォルダーを、実際の場所に直したもの（ログフォルダー自体がシンボリックリンクのときは、リンク先）。Redmine が立ち上がってから最初に使うときに決める。

次のものは一覧に並ばず、読むこともできない。

- 下のフォルダー（とその中のファイル）
- シンボリックリンク
- 普通のファイルでないもの（名前付きパイプなど）
- ハードリンクが 2 つ以上あるもの
- Redmine を動かしているユーザーが読めないもの（logrotate が root だけ読めるように作った `.gz` など）
- 名前が UTF-8 でないもの、`/`・`\`・`:`・NUL を含むもの、`.` で始まるもの

## GET /server_logs.json

ログフォルダーの直下にある、読めるファイルの一覧（名前の順）。

```json
{
  "server_logs": {
    "log_file": "production.log",
    "files": [
      { "name": "production.log", "size": 5368709120, "updated_on": "2026-11-21T09:12:03+09:00", "fingerprint": "4096:9f2c…e1" },
      { "name": "production.log.1", "size": 10955669504, "updated_on": "2026-11-14T03:00:01+09:00", "fingerprint": "4096:41ab…7c" },
      { "name": "production.log.2.gz", "size": 1181116006, "updated_on": "2026-11-07T03:00:02+09:00", "fingerprint": "4096:c0d3…88", "compressed": true }
    ]
  }
}
```

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `log_file` | string / null | 今 Redmine のロガーが書いているファイルの名前。ファイルに書いていない（標準出力・syslog に出している など）ときや、ログフォルダーの外のファイルのときは `null` |
| `files` | array | ファイルの一覧。ログフォルダーが無い・読めないときは空 |

### files 配列

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `name` | string | ファイルの名前（フォルダーを含まない） |
| `size` | integer | 大きさ（バイト）。圧縮されたファイルは、圧縮したままの大きさ |
| `updated_on` | string | 最後に書かれた日時（サーバーの時刻。時差つき） |
| `fingerprint` | string / null | ファイルの見分けの印（下の「見分けの印」）。圧縮されたファイルが壊れていて取れないときは `null` |
| `compressed` | boolean | gzip で圧縮されたファイルのとき `true`（名前が `.gz` で終わり、先頭が gzip の形）。それ以外は省く |

### 見分けの印（fingerprint）

`対象にしたバイト数:その SHA-256（16 進の小文字）` の形。対象はファイルの先頭の 4096 バイト（ファイルがそれより小さければ全体）。

- 圧縮されたファイルは、展開した先頭で取る。ローテーションのあとすぐに圧縮されても、元のファイルと同じ印になる
- 中身が空のファイルは `"0:"`

ローテーションで名前が変わったファイルを見つける・読んでいる間に入れ替わっていないかを確かめる、のに使う。

## GET /server_logs/content.json

指定したファイルの、指定した範囲のバイトを、そのまま返す（圧縮されたファイルも、圧縮したままのバイト）。

### パラメータ

| パラメータ | 必須 | 説明 |
|-----------|------|------|
| `name` | ○ | 一覧の `name` と完全に一致すること（Windows のサーバーでは大文字・小文字を区別しない） |
| `offset` | ○ | 読み始める位置（バイト。0 以上の整数） |
| `length` | | 読みたい量（バイト。1 以上の整数）。省くと 16 MB。下の上限で短くなることがある |
| `fingerprint` | | 一覧で受け取った印。渡したときは、同じバイト数で今のファイルの印を取り直して比べ、違えば 409 を返す。今のファイルがそのバイト数より短いときも 409 |

### 1 回に返す量の上限

次のどちらかに達したところで止める。

- 送る量（圧縮した後）がおよそ 1 MB
- 読んだ量が 16 MB

求めた量より短く返ることがあるので、続きは `offset` を進めて読む。

### レスポンス（成功）

- ステータス 200。本文は範囲のバイト（`Content-Type: application/octet-stream`）
- リクエストの `Accept-Encoding` に `gzip` があり、ファイルが圧縮されていなければ、本文を gzip で圧縮して返す（`Content-Encoding: gzip`）。圧縮されたファイルは圧縮し直さない
- `offset` がファイルの大きさ以上のときは、本文が空の 200

| ヘッダー | 説明 |
|---------|------|
| `X-Server-Log-Size` | 開いたファイルの、今の大きさ（バイト） |
| `X-Server-Log-Length` | 返した量（圧縮する前のバイト） |
| `Cache-Control` | `no-store`（ログを途中のプロキシなどに残さない） |

読み終わりは、`offset + X-Server-Log-Length >= X-Server-Log-Size` で判断する（返した量が求めた量より短いことだけでは、終わりと判断しない）。

### レスポンス（失敗）

| ステータス | いつ |
|-----------|------|
| 401 | API キーが無い・無効 |
| 403 | システム管理者でない |
| 404 | `name` が一覧に無い（並ばないもの・消えた・ログフォルダーの外）。プラグインが古くて API が無いときの 404 とは、本文が JSON かどうかで見分けられる |
| 409 | `fingerprint` が今のファイルと違う。ヘッダー `X-Server-Log-Size` に今の大きさ、本文の `fingerprint` に今の印を付ける |
| 422 | `name` が無い、`offset`・`length` が整数でない・負の数・（`length` が）0、`fingerprint` の形が違う |
| 429 | 読み出しが同時に 2 つ走っている。ヘッダー `Retry-After: 2`（秒）。その秒だけ待って取り直す |

```json
{ "errors": ["fingerprint does not match the current file"], "fingerprint": "4096:41ab…7c" }
```

### 同時に読める数

読み出しは、サーバーごとに同時に 2 つまで。Redmine の `tmp` フォルダーにロックのファイル（`redmine_studio_plugin_server_logs_read_0.lock`・`_1.lock`）を置いて数える。プロセスやスレッドをまたいで数え、プロセスが落ちてもロックは自然に外れる。

- 複数台のサーバーなら、それぞれで 2 つまで
- `tmp` が NFS の上にあるときは、数えられないことがある
- `tmp` に書けないときは、数えずに読む（Redmine のログに 1 回だけ警告を書く）

ロックを持つのは、1 回の読み出しの間だけ。サーバーの負担を抑えるため、呼ぶ側は 1 つずつ順に読むこと。

## 使い方の例

1. `GET /server_logs.json` で一覧を取る。`log_file` で始まる名前のファイルが、Redmine のログとそのローテーション後のファイル
2. `GET /server_logs/content.json?name=production.log.1&offset=0&fingerprint=…` を `Accept-Encoding: gzip` を付けて呼ぶ
3. `offset` に `X-Server-Log-Length` を足して、`offset >= X-Server-Log-Size` になるまで繰り返す
4. 409 なら、本文の今の `fingerprint` で一覧を見直す（ローテーションで入れ替わった）。429 なら `Retry-After` の秒だけ待つ

この API へのリクエストも Redmine のログに書かれる（パスに `/server_logs` を含む）。

## 作らないもの

- ログの削除・書き込み（読むだけ）
- 下のフォルダーのログ
- サーバー側での検索・集計
