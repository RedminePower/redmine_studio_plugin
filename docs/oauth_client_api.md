# OAuth Client API

ブラウザサインイン（OAuth2.0 + PKCE）を開始するために必要な `client_id` と権限範囲（scopes）を、
認証情報なしで取得する API。Redmine Studio が起動時の対応判定とサインイン開始に使用する。

## エンドポイント一覧

| エンドポイント | 説明 |
|---------------|------|
| `GET /oauth_client.json` | サインイン用 client_id / scopes の取得 |

## 認証

**この API は匿名（認証情報なし）でアクセスできる。** Redmine 本体の「認証が必要」設定に関わらず到達できる。

Redmine Studio のプラグインが追加する API のうち、匿名アクセスを許可するのはこの API だけである。
サインインを開始する前段ではまだアクセストークンが無く、その状態で `client_id` を取得する必要があるため。
返す情報は `client_id` と `scopes` のみに限定している。

## レスポンス形式

API は JSON と XML の両方をサポートする。

| 拡張子 | Content-Type |
|--------|--------------|
| `.json` | application/json |
| `.xml` | application/xml |

---

## サインイン用クライアント情報

### GET /oauth_client

サインイン用 OAuth アプリの `client_id` と、要求する権限範囲（`scopes`）を取得する。

**登録済み（Redmine 6.1 以上・サインイン可能）:**

```json
{
  "oauth_client": {
    "client_id": "dZ_kPCxn3ilJ7HH36iV3DhLG9e2DX645xCIYGW-lHjc",
    "scopes": [
      "add_issues",
      "edit_issues",
      "view_issues",
      "view_time_entries",
      "log_time"
    ]
  }
}
```

**未登録（Redmine 6.1 未満など・サインイン非対応）:**

```json
{"oauth_client":{}}
```

`oauth_client` ルートは常に返し、`client_id` / `scopes` は登録済みのときだけ含める。

---

## レスポンスフィールド

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `client_id` | string | サインイン用 OAuth アプリの client_id |
| `scopes` | array | 要求する権限範囲（Redmine の権限名の配列） |

---

## 3 つの応答パターン

| 状態 | 応答 |
|---|---|
| サインイン可能（Redmine 6.1 以上 かつ 登録済み） | `200` `{ "oauth_client": { "client_id": "...", "scopes": [...] } }` |
| 対応版プラグインは在るが環境未対応（6.1 未満・未登録） | `200` `{"oauth_client":{}}`（`client_id` 無し） |
| プラグイン未導入・旧版 | `404`（この API 自体が存在しない） |

`client_id` が返るかどうかがサインイン可否と一致する。

---

## サインイン用 OAuth アプリの自己修復登録

サインインに使う OAuth アプリ（公開クライアント）は、Redmine の起動のたびに自動で登録される。

- 未登録なら登録する（プラグインを先に入れ、Redmine を後から 6.1 に上げた場合でも、いずれ整合する）
- 秘密鍵を持たない公開クライアント（`confidential=false`）として登録する（Redmine の管理画面からは作成できないため）
- リダイレクト先はループバック（`http://127.0.0.1/`）。実際に使うポート番号が異なっていても問題ない
- 権限範囲は下記方針で定義し、定義が変わった場合は登録側も追従する

### 権限範囲（scopes）の方針

| 区分 | 内容 |
|------|------|
| 閲覧系 | 閲覧用の権限を広めに許可（破壊的操作は除外） |
| 変更系 | アプリが実際に使う操作のみ（チケットの作成・更新・注記、時間記録の登録・更新・削除） |
| 管理系 | 管理者権限は含めない |

トークンに載る権限と利用者本人の権限は AND で効くため、利用者が Redmine 上で見えない情報はサインインしても見えない。

## 前段 Basic 認証ゲート下でのトークン取得

Redmine の手前にリバースプロキシで HTTP Basic 認証（前段ゲート）を置いた構成でも、ブラウザサインインの
トークン取得（`POST /oauth/token`）が成立するようにしている。

前段ゲートを通すため、クライアントは `Authorization: Basic` にゲートの資格情報を載せる。ところが標準の
Doorkeeper はこのヘッダを OAuth クライアントの資格情報（`client_id:client_secret`）として解釈するため、
ゲートの資格情報では該当クライアントが見つからず `invalid_client` でトークン取得に失敗してしまう。

本プラグインは、`Authorization: Basic` のユーザー名が「登録済み OAuth アプリの `client_id`（uid）」でない
場合に限り、それをクライアント資格情報として扱わないようにする。これにより前段ゲートの資格情報は無視され、
リクエストボディの `client_id`（公開クライアント）でクライアントが識別され、トークン取得が成立する。

- 前段ゲートが無い通常構成には影響しない（Basic ヘッダが無ければ従来どおり）
- 登録済みアプリの `client_id` を用いた正規のクライアント Basic 認証はそのまま尊重する
- 顧客側のプロキシ設定（特定パスの Basic 除外など）を追加する必要はない
